# Bitácora de Desarrollo — 2026-10-14

## Resumen de la Jornada
Ejecución integral de los **Bloques 1, 2, 3 y 4** del proyecto LIS (UTN FRC), abarcando:
- **Fase 0:** Portabilidad, configuración externa `config.toml` y cámara universal (Webcam, DroidCam por Wi-Fi/IP y modo simulado).
- **Fase 1:** Persistencia SQLite nativa con modo WAL, Event Sourcing inmutable, adaptadores de destinos y resolución del bug de reingresos.
- **Fase 2:** Protocolo serie del Fichador (115200 baudios, delimitado por `|`, truncado a 16 caracteres para display LCD 16x2) y modo simulado virtual.
- **Fase 3:** Servicio del Portero HTTP (Galileo / Borde) con biblioteca estándar de Python exclusively, persistencia append-only en `JSONL` con `os.fsync`, y sincronizador pull del Servidor con cursor tolerante a cortes.
- **Fase 4:** Pipeline de reconocimiento facial de alto rendimiento (FaceNet rápido sin doble pasada por MTCNN), matching vectorizado multi-muestra y caché de "Cara Estable" para triplicar los FPS en CPU.
- **Fase 5 (Adelanto):** Tablero web responsive unificado (`tablero/index.html`) para celulares y tablets, con streaming MJPEG en vivo (`/video_feed`), LCD RGB virtual con Web Audio API, presentes, inventario, avisos y simulador de sensores.

## 1. Módulos y Arquitectura Implementada

### A. Complemento de Cámara Universal (`hardware/camara.py`)
- Clase `FuenteDeVideo` que soporta tres modos de operación sin modificar el código del pipeline:
  1. **Webcam USB / Driver virtual (`indice = 0, 1...`):** Soporte de backends DirectShow y V4L2.
  2. **Stream IP / DroidCam Wi-Fi (`url_stream = "http://..."`):** Lector de video en hilo independiente con buffer de 1 solo cuadro para eliminar el retraso de transmisión típico de streams HTTP de teléfonos móviles. Reintento automático de conexión ante caídas.
  3. **Cámara Simulada (`indice = "simulada"`):** Canvas interactivo a 30 FPS para desarrollo y pruebas completas sin periféricos conectados, con soporte de disparos manuales (`I`, `E`, `T`).
- Mecanismo en memoria para exportación de cuadros procesados a JPEG (`guardar_frame_jpeg` y `obtener_frame_jpeg`) para alimentar el streaming web.

### B. Persistencia y Event Sourcing (`nucleo/eventos.py`, `nucleo/destinos.py` y `nucleo/base_datos.py`)
- Esquema de eventos oficial de la Sección 6: `id`, `tipo`, `persona_id`, `objeto_id`, `t`, `reloj_confiable`, `origen`, `metodo`, `distancia`, `meta`.
- Función `derivar_estado(lista_eventos)` que computa:
  - Personas presentes y conteo exacto de reingresos diarios.
  - Equipos en préstamo (`retiro` y `devolucion`).
  - Avisos activos (`aviso_creado` y `aviso_cerrado`).
  - Anulaciones retroactivas mediante eventos de tipo `correccion`.
  - Parámetros de ambiente (`lux`, `temperatura`, `ruido`) y modo del laboratorio.
- Adaptadores `DestinoSQLite`, `DestinoCSV`, `DestinoPorteroHTTP` (con cola local de reintentos `datos/cola_pendientes.jsonl` offline-first) y `DestinoCompuesto`.

### C. Protocolo Serie del Fichador (`hardware/serie.py`, `hardware/fichador/`)
- Cliente serie a 115200 baudios con truncado de textos a 16 caracteres para display 16x2.
- Comandos: `MSG|l1|l2`, `RGB|r|g|b`, `BEEP|ok/err/warn`, `LED|color|0/1`, `PING` -> `PONG`.
- Modo Simulado interactivo que sincroniza el estado virtual del display LCD, color RGB de fondo y LEDs para la interfaz web.
- Sketch Arduino `hardware/fichador/fichador.ino`, guía de puertos `hardware/fichador/README.md` y documentación `docs/PROTOCOLO_SERIE.md`.

### D. Servicio del Portero HTTP (`portero/servidor_portero.py`)
- Servidor HTTP multi-hilo desarrollado **exclusivamente con la biblioteca estándar de Python** (`http.server`, `json`, `urllib`, `socket`, `os`, `pathlib`, `uuid`).
- Persistencia en `datos/portero_eventos.jsonl` con `os.fsync` y deduplicación por `id`.
- Endpoints implementados:
  - `POST /events`: registro idempotente de eventos.
  - `GET /events?since=<cursor>`: paginación por cursor para sincronización pull.
  - `GET /state`: estado derivado analítico en tiempo real + estado de hardware.
  - `GET /health`: estado del nodo, hora UTC, eventos acumulados y confiabilidad de reloj.
  - `GET /tablero`: servicio de la interfaz web responsiva.
  - `GET /video_feed`: streaming MJPEG `multipart/x-mixed-replace` para visualización en navegadores móviles.
  - `POST /camara/configurar`: cambio en caliente de fuente de video (USB, DroidCam o Simulada).
  - `POST /hardware/accion`: recepción de acciones táctiles y eventos simulados desde el celular.

### E. Sincronizador por Pull del Servidor (`servidor/sincronizador.py`)
- Consulta periódica al Portero y persistencia en la base maestra SQLite (`datos/lis_maestra.db`) y CSVs en espejo.
- Cursor confirmado en disco (`datos/servidor_cursor.txt`).
- Control de pausa/reanudación para simular el apagado del servidor central sin pérdida de datos en el borde.

### F. Tablero Web Unificado (`tablero/index.html`)
- Desarrollado en HTML5/CSS3/JS puro, optimizado para celulares y tablets en formato vertical u horizontal.
- Tres modos conmutables:
  1. **Fichador & Cámara:** Transmisión de video con cajas faciales y distancias en vivo, display LCD 16x2 reactivo con sonido Web Audio API, botón táctil gigante `TOUCH`, gestos simulados y fichado por PIN/QR.
  2. **Tablero de Pared:** Tarjetas de presentes con distancias crudas, control de préstamos de inventario, pizarrón de avisos y visor de eventos append-only.
  3. **Simulador de Sensores:** Perilla rotatoria para PIN de Caja Fuerte Galileo, controles deslizantes de la Torre de Estado (luz, temp, ruido) y simulador de servidor encendido/apagado.

### G. Script Lanzador Todo-en-Uno (`iniciar_demo.py`)
- Detección automática de la IP local de red Wi-Fi/LAN.
- Coordinación e inicio concurrente de Portero HTTP, Sincronizador Pull y Pipeline de visión.
- Banner de instrucciones en consola con URLs directas para la PC y para el navegador del celular.

## 3. Guía de Ejecución y Pruebas con Celular

### Opción 1: Celular como Tablero / Fichador Táctil (con Webcam USB en PC)
1. Ejecutar en la PC:
   ```bash
   python iniciar_demo.py
   ```
2. La consola mostrará la dirección de red local (ejemplo: `http://192.168.1.45:8080/tablero`).
3. Abrir esa URL en el navegador del celular o tablet conectado al mismo Wi-Fi para interactuar con la cámara en vivo, el LCD virtual y los presentes.

### Opción 2: Celular como Cámara Inalámbrica (DroidCam por Wi-Fi)
1. Abrir la app **DroidCam** en el celular.
2. Iniciar el sistema especificando la URL del stream:
   ```bash
   python iniciar_demo.py --camara http://192.168.1.XX:4747/video
   ```
   *(También se puede pegar la URL de DroidCam directamente desde el campo de texto en el Tablero Web)*.

### Opción 3: Modo 100% Simulado (Sin cámara ni Arduino)
```bash
python iniciar_demo.py --camara simulada
```
Permite probar todo el circuito de eventos, gestos por teclado (`I`, `E`, `T`) o botones web sin requerir ningún dispositivo físico.
